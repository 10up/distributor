id: receiving-posts
title: "Receiving Distributed Posts"
---

A site can receive a distributed post by several routes. Each route has its own push or pull hooks. The `dt_receive_post_*` hooks run on the receiving site for every route, so a single callback covers both new posts and later updates from the origin.

## Receive routes

| Route | Connection type | When it runs | Where the code runs |
|---|---|---|---|
| `push` | `internal` | The origin pushes a post, or updates a post it pushed before. | The origin site's request, after `switch_to_blog()` to the receiving site. |
| `pull` | `internal` | The receiving site pulls a post. | The receiving site. |
| `push` | `external` | The origin pushes a post through the REST API. | The receiving site's REST API request. |
| `pull` | `external` | The receiving site pulls a post. | The receiving site. |
| `subscription` | `external` | The origin updates a post that it pushed, or that the receiving site pulled. | The receiving site's subscription REST API endpoint. |
| `relink` | `external` | An editor relinks an unlinked post. Distributor applies the last update it stored from the origin. | The receiving site. |

When an editor relinks a network post, the origin pushes the post again. That relink runs as an `internal` `push`.

### Network sites

For network connections, the receive hooks often run in the origin site's PHP request. Plugins that are active only on the receiving site are not loaded in that request. Put receive callbacks in a network activated plugin or in mu-plugins so they run for every route.

## Receiving Hooks

| Hook | Type | Runs |
|---|---|---|
| `dt_receive_post_args` | Filter | Before the post is inserted or updated. |
| `dt_receive_post_meta` | Filter | Before the post meta is set. |
| `dt_receive_post_terms` | Filter | Before the post terms are set. |
| `dt_receive_post_media` | Filter | Before media is downloaded and attached. |
| `dt_receive_post` | Action | After the post, meta, terms and media are saved. |

The route-specific hooks run first. For example, `dt_pull_post_meta` returning `false` skips meta processing. In that case `dt_receive_post_meta` does not run.

### Context

Every receive hook gets a `$context` array as its last argument.

| Key | Type | Description |
|---|---|---|
| `source` | `string` | How the post arrived: `push`, `pull`, `subscription` or `relink`. |
| `connection_type` | `string` | `internal` for a network site, `external` for an external connection. |
| `is_update` | `bool` | `true` when Distributor updates an existing post, `false` when it creates one. |
| `post_id` | `int` | The receiving site's post ID. It is `0` in `dt_receive_post_args` when Distributor creates a post. |
| `original_post_id` | `int` | The post ID on the origin site. |
| `connection` | `Connection\|null` | The connection object. It is `null` for external pushes, subscription updates and relinks, because the receiving site has no connection object on those routes. |

### `dt_receive_post_args`

Filters the arguments passed to `wp_insert_post()` or `wp_update_post()`.

```php
apply_filters( 'dt_receive_post_args', array $post_args, array $context );
```

The arguments differ by route.

- Pushes and pulls send the full set of post fields.
- Subscription updates and relinks send only the title, content, excerpt and, for subscriptions, the slug. Distributor always resets `ID` to the post being updated.
- External pushes filter the REST API's prepared post. Distributor converts it to an array for the filter, then back to an object.

### `dt_receive_post_meta`, `dt_receive_post_terms` and `dt_receive_post_media`

Filter the meta, terms or media before Distributor saves them.

```php
apply_filters( 'dt_receive_post_meta', array $meta, array $context );
apply_filters( 'dt_receive_post_terms', array $terms, array $context );
apply_filters( 'dt_receive_post_media', array $media, array $context );
```

Return an array to save it. Return `false` to skip that step.

Media is the only step that downloads files. Remove items from the `$media` array to skip their download. Each item has the format from `\Distributor\Utils\prepare_media()`, which includes `source_url` and `featured`.

Subscription updates and external pushes remove the featured image when the origin sends no media. Returning `false` from `dt_receive_post_media` does not remove the featured image.

### `dt_receive_post`

This action after the post, meta, terms and media are saved. It does not fire when the insert or update fails.

```php
do_action( 'dt_receive_post', int $post_id, array $context );
```

## Examples

### Keep a local excerpt on updates

```php
add_filter( 'dt_receive_post_args', function( $post_args, $context ) {
	if ( $context['is_update'] ) {
		unset( $post_args['post_excerpt'] );
	}

	return $post_args;
}, 10, 2 );
```

### Skip media downloads for updates

```php
add_filter( 'dt_receive_post_media', function( $media, $context ) {
	if ( $context['is_update'] ) {
		return false;
	}

	return $media;
}, 10, 2 );
```

### Replace all images with one image

This example replaces every image from the origin with `cat.png`. Other media, such as PDFs, is kept. If an origin image was the featured image, `cat.png` becomes the featured image.

```php
add_filter( 'dt_receive_post_media', function( $media, $context ) {
	$cat_url  = 'https://example.com/wp-content/uploads/cat.png';
	$featured = false;
	$kept     = array();

	foreach ( $media as $media_item ) {
		if ( isset( $media_item['media_type'] ) && 'image' === $media_item['media_type'] ) {
			if ( ! empty( $media_item['featured'] ) ) {
				$featured = true;
			}

			continue;
		}

		$kept[] = $media_item;
	}

	// The origin sent no images.
	if ( count( $kept ) === count( $media ) ) {
		return $media;
	}

	$kept[] = array(
		'id'          => 0,
		'title'       => 'cat',
		'featured'    => $featured,
		'source_url'  => $cat_url,
		'source_file' => '',
		'media_type'  => 'image',
		'mime_type'   => 'image/png',
		'caption'     => array( 'raw' => '' ),
		'description' => array( 'raw' => '' ),
	);

	return $kept;
}, 10, 2 );
```

- Distributor downloads `cat.png` once for each received post. Later updates to that post reuse the attachment, because Distributor matches it by its original URL.
- An empty `source_file` makes Distributor download the file, even for network sites.
- Image URLs in the post content still point to the origin images. Use `dt_receive_post_args` to change the content as well.

### Log every received post

```php
add_action( 'dt_receive_post', function( $post_id, $context ) {
	error_log(
		sprintf(
			'Distributor received post %d by %s (%s).',
			$post_id,
			$context['source'],
			$context['connection_type']
		)
	);
}, 10, 2 );
```
